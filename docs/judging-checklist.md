# Judging and submission checklist

## Build

- [ ] Web simulator installs and builds from a fresh checkout.
- [ ] MCP service installs, tests, and starts without cloud credentials.
- [ ] `/mcp` is verified with MCP Inspector or another compatible client.
- [ ] All six tool flows work with the fictional demo household.
- [ ] Safety language appears in the interface and README.
- [ ] Optional Bedrock path is either demonstrated or described only as
      optional/not configured.

## Repository

- [x] MIT license included.
- [ ] Public GitHub repository created.
- [ ] Repository About section shows the license.
- [ ] Setup, build, test, and troubleshooting commands verified.
- [ ] No credentials, personal data, generated secrets, or `.env` files.

## Media

- [x] 3:2 project thumbnail created locally.
- [ ] Three to five gallery screenshots captured.
- [ ] Public YouTube or Vimeo demo uploaded.
- [ ] Video shows the working simulator plus a separate MCP-client demo—not only slides.

## Devpost

- [x] Project name and elevator pitch saved.
- [x] Submitter type chosen by the user: Individual.
- [ ] Project story entered after final technical verification.
- [ ] Built-with tags entered.
- [ ] GitHub URL entered.
- [ ] Demo URL and video URL entered.
- [x] Country of residence supplied by the user: India.
- [ ] Alexa+ primary track selected.
- [ ] AWS Builder selected only if the AWS integration is documented and shown.
- [ ] Feedback questions answered from actual development experience.
- [ ] Eligibility attestations reviewed by the user.
- [ ] Final submission reviewed and explicitly approved by the user.
